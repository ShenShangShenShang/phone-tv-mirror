# 投屏协议与实现

两端都是手写代码，没有第三方 SDK。这份文档是给要改代码的人看的。

---

## 一、协议（TCP 9000，手机 → 电视）

### 握手

```
"MRR1" (4 字节 ASCII) + int csdLen + csd(SPS/PPS) + int width + int height
```

电视端读到前 4 字节不是 `MRR1` 会打印 `未知握手: ...` 并断开——这条日志是排查时的第一现场。

### 数据帧

```
int length + bytes
```

`length` 为正数是视频帧；负数表示控制包：

| 值 | 含义 | 附加数据 |
|---|---|---|
| `-1` | 重配（分辨率变化） | int csdLen + csd + int w + int h |
| `-2` | 音频 CSD | int len + bytes |
| `-3` | 音频帧 | int len + bytes |
| `-4` | **音量百分比** | int pct（0–100） |
| `-5` | 故障文案 | int len + UTF-8 文本 |

### UDP 发现（9100）

手机往 `255.255.255.255:9100` 广播 `MIRROR-FIND`，电视端收到回 `TVMIRROR:9000`。
手机取回包的**来源地址**当电视 IP，所以电视重启换了 IP 也不用改配置。

手机端 `setSoTimeout(2500)`、只 `receive` 一次，扫到或者超时就回调。

## 二、编码参数

- 视频：`video/avc`，5 Mbps，30 fps，I 帧间隔 1 秒。
  **Baseline + AVCLevel31** —— 4.3 时代的硬解器只认这个，用 High profile 会直接不出图。
- 音频：`audio/mp4a-latm`，44100 双声道，128 kbps。
- 采集尺寸：长边压到 1280，短边 16 对齐。竖屏 576×1280，横屏 1280×576。
- 音频源：`AudioPlaybackCaptureConfiguration`（USAGE_MEDIA / GAME / UNKNOWN）。
  **Android 10（API 29）以下没有这个 API，直接返回，不送音频。**

## 三、转屏：为什么必须重新申请授权

Android 14 起，同一份 `MediaProjection` 只允许建**一个** `VirtualDisplay`。
想换分辨率重建会直接抛：

```
SecurityException: 这个系统不允许切换方向
```

**所以转屏只能换一份新授权。** 流程：

1. 采集线程检测到尺寸变化 → 置 `rotateWaiting`，不自己重建。
2. 拉一个透明 Activity `ReauthActivity` → `createScreenCaptureIntent()` → 系统弹授权框。
3. 用户点允许 → `onActivityResult` 拿到新的 `resultCode/data` → `startForegroundService` 带 `ACTION_REBUILD`。
4. Service 里：停音频 → 拆旧 display / encoder / surface / projection → 用新授权重建 → 重启音频。
5. **socket 不动**，只发一个 `-1` 让电视端重配解码器。

### 让"只弹一次"成立的几个细节

这几个不是锦上添花，缺一个就会出问题：

- `ReauthActivity` 用独立 `taskAffinity` + `launchMode="singleTask"`：授权页关掉后回到用户
  原来的应用，不会把本 App 主界面拉到前台。
- **不能加 `noHistory`**：系统授权框一弹、页面失焦，加了 `noHistory` 的 Activity 立刻被销毁，
  `onActivityResult` 直接收不到，表现就是"权限点了却没生效"。
- `screenOrientation="behind"`：授权页跟着下面那个 Activity 的方向走，不把用户正在横屏看的画面掰回竖屏。
- `configChanges="orientation|screenSize|smallestScreenSize|screenLayout|keyboardHidden|density|uiMode"`：
  `behind` 会让它在方向变化时**自己重建一次**，一重建就又弹一个框（用户看到的是"问两遍权限"）。
- `onCreate` 里 `if (savedInstanceState != null) return;` 兜底，防重建后再弹。
- **会话代号**（`projGen`）：旧会话的 `onStop` 回调会异步迟到，带着旧代号回来时不能再把主循环停掉。
  代号必须在"拆旧链路之前"递增，不能等新会话建好才加——中间那段空档里旧回调会被误认成当前会话。

## 四、并发：两条发送线程会互抢编码器

这是最容易被用户"点出来"的 bug：点开始 → 电视黑着 → 几秒后中断 → **点一下停止再连就好了**。

原因：`onStartCommand` 收到两次 `ACTION_START`（用户连点，或上一轮还没退就又来一发），
两个 `runMirror` 共用同一个 `encoder` / `socket` 字段：

```
java.lang.IllegalStateException:
  Invalid to call while another dequeue output request is pending
  at MirrorService.runMirror(...)
```

两条线程一起死。电视端只会看到 `未知握手` + `EOFException`。

**修法（两层）**：

1. 服务端：新会话进来时，若旧线程还活着，先 `running = false`，`join(1500)` 等它退干净，再起新的。
2. 收尾用 `stopSelf(startId)` 而不是 `stopSelf()`——旧会话退出时只停自己，不会误杀用户刚点的那一轮。
3. 界面点开始后按钮锁 8 秒（覆盖"扫描 2.5 秒 + 等授权"），从源头减少连点。

## 五、电视端上屏：SurfaceView + awaitFreshSurface

踩过的两条死路：

| 方案 | 结果 |
|---|---|
| `SurfaceView` 直接改 View 尺寸 | **黑屏**。改尺寸会销毁重建底层 Surface，解码器还挂在旧的 |
| `TextureView` + `setTransform(Matrix)` + `setDefaultBufferSize` | **变形**，参数全对也不行（个别老固件的矩阵不生效） |

可用方案：**`SurfaceView` + `awaitFreshSurface(2500)`**。

改 `LayoutParams` 后，SurfaceView 会销毁旧 Surface 并重建；这里用 `SurfaceHolder` 回调
（`surfaceCreated` / `surfaceChanged` / `surfaceDestroyed`）递增一个序号，主循环等序号变化，
拿到新 Surface 再 `configure` 解码器。等不到（尺寸其实没变）就退回原来那块。

### 显示区算法

按比例等比缩放并居中，剩余区域留黑：

```java
if (videoRatio > screenRatio) { nw = sw; nh = (int)(sw / videoRatio); }
else                         { nh = sh; nw = (int)(sh * videoRatio); }
```

手机 2340×1080 与电视 1920×1080 比例天生不同，所以必然有黑边。**这里选择不裁任何内容**。
如果你要"填满"，把算法改成按高度铺满（`nh = sh; nw = (int)(sh * videoRatio)`），
超出的部分靠父容器裁掉即可——代价是画面最边缘一条看不见。

**不要试图做"智能检测黑边"**：那需要把解码帧拉回 CPU 逐像素扫，
在 1GB 内存的老方案盒子上会直接吃掉帧率，而且判不准（电影上下本来就有黑边）。

## 六、音频增益：为什么不用系统音量

问题：投屏的声音比电视自带节目响得多，每次投屏都要手动调电视音量，投完还得调回去。

原因：两路 PCM 的**满幅电平**就不一样，加上响度是对数的，差一点听着差很多。

**做法**：不改系统音量，改**这一路 PCM 的增益**：

```java
out = pcm[i] * gain;   // gain 默认 0.15
if (out > 32767) out = 32767;
if (out < -32768) out = -32768;
```

- 手机端滑块 0–100 对应 0–1.0，通过 `-4` 指令下发；0 就是彻底静音。
- 电视端默认 0.15；遥控器上下键/音量键微调，步长 0.05，下限 0；**重连不重置**。
- 手机端握手完成后补发一次当前音量，保证重连后还是上次调好的值。

注意：`-4` 的百分比必须从 `startForegroundService` 的 Intent 里**带进来**。
只靠字段默认值的话，界面显示 1%、电视实际按 15% 播，只有手动动一下滑块才对得上——
这个 bug 的真实表现就是"我设了 1%，声音还是那么大"。

## 七、通知与前台服务

Android 8+ 前台服务启动后 **5 秒内必须挂出通知**，否则进程被杀。所以：

- `ACTION_START` 一进来就 `startForeground(..., "正在连接 host …")`；
- 握手完成（画面真的上墙）→ 改成 `正在投屏 WxH · 音量 N%`；
- 停止 / 断开 / `onDestroy` 三处都 `stopForeground(true)`，通知栏不留尾巴；
- 单独的音量指令（`ACTION_GAIN`）在没投屏时直接 return，不为它挂通知。

## 八、调试口

手机端内置一个只读 HTTP 服务（端口 9999）：

```
http://<手机IP>:9999/file   落盘日志（超 300KB 自动重置；进程死了也还在）
http://<手机IP>:9999/       内存环形缓冲（400 行）
```

查"连不上"这类问题，这个口比 logcat 好用：不需要 adb，掉线后日志也还在。
