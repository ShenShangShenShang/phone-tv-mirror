# 常见问题

按症状查。每条都是实际遇到过的。

---

## 投屏类

### 点开始，电视一直黑着，几秒后手机上显示中断；点一下"停止"再连就好了

两条发送线程抢同一个编码器。日志特征：

```
连接电视 ...
已发 54 帧 ...
连接电视 ...          ← 3 秒内又起了一轮
投屏中断: Invalid to call while another dequeue output request is pending
发送线程退出 / 发送线程退出
```

1.0 版已经加了服务端互斥 + 界面锁按钮。如果还出现，说明还有第三处在重复发 `ACTION_START`，
把日志按时间戳发出来。

### 电视端日志 `未知握手: <乱码>`

不是协议本身坏了，是手机端在**半死状态下写出去的残缺数据包**（通常是上面那种并发冲突的余波）。
先修并发，再看这条。

### 转屏之后要弹两次授权

授权页 `ReauthActivity` 被系统重建了一次。检查这几项是否齐全：

- `configChanges` 包含 `orientation|screenSize|...`
- `onCreate` 里判 `savedInstanceState != null` 直接 return
- `launchMode="singleTask"` + 独立 `taskAffinity`
- **没有** `noHistory`

### 转屏之后黑屏、或者干脆投不上了

看日志里有没有 `已按新方向重建` 和 `发送线程退出` 只隔几毫秒。
如果是，就是**会话代号递增的时机错了**：`projGen++` 必须放在"拆旧链路之前"，
不能等新会话建好才加，否则旧会话迟到的 `onStop` 会把自己当成当前会话，把主循环停掉。

### 手机横屏后四周一圈黑边

比例差异，不是 bug。手机横向 2340×1080（2.167）比电视 1920×1080（1.778）更宽，
等比缩放后是 1920×864，上下各留 108px；**左右那两条黑边来自手机画面本身**
（很多 App 横屏时视频只占屏幕中间）。

要么等比显示（有黑边、不裁内容），要么裁边填满（没黑边、边缘一条看不见）。
没有第三个选项，也不建议做逐像素检测黑边。

### 投屏声音比电视自带节目响得多

不要调电视系统音量。用手机端的**投屏音量滑块**，它改的是这一路 PCM 的增益，
不动系统音量，所以投完换个节目不用再调回去。默认 15% 大致相当于比满幅小一档。

参考量：同一台电视用自带节目时系统音量 30，投屏要 10 才差不多；按增益算是降到约 30%。

### 我在 App 里设了 1%，实际却按 15% 播

v3.0 以前的 bug：`startForegroundService` 的 Intent 没带音量，服务用了字段默认值。
现在 `ACTION_START` 会读 `EXTRA_GAIN` 并裁到 0–100。如果还不对，检查是不是没重新安装。

## 连接类

### 收不到电视 / 一直"正在搜索"

按顺序：

1. 电视端 App **必须在前后台**（它不在前台就不应答发现广播）。
2. 手机和电视在同一网段（IP 前三段一致）。
3. 路由器关了「AP 隔离 / 访客网络隔离」。
4. 电视刚从路由器换了 IP——本工具是 UDP 发现的，不依赖固定 IP，但如果电视刚重启完还没连上 WiFi，
   等它联网再点开始。

### 能发现电视，但连 9000 端口超时

- 电视端 App 被系统清理了，重开会；
- 电视上有别的进程占用了 9000（`busybox netstat -tln | busybox grep 9000` 查）；
- 手机在另一个 VLAN / VPN 里。

### 投着投着就断了，手机端进程被杀

1. 通知权限没给——前台服务通知显示不出来，系统会当普通后台服务杀；
2. 电池优化白名单没开；
3. 悬浮窗没给；
4. 国产 ROM 的"自启动管理"没开（**这一项不是必须的**，前三条齐了基本够用；
   真被杀了再去设置里点「自启动管理」跳过去开）。

## 电视侧（Android 4.3 / 老固件）

### `screencap -p` 输出 0 字节，没法截图

老固件常见。改用：

```bash
adb shell "uiautomator dump /data/local/tmp/ui.xml && cat /data/local/tmp/ui.xml"
adb shell "dumpsys window | busybox grep mCurrentFocus"
```

纯自绘桌面的 App（比如 Aerial）`uiautomator dump` 里文字全空，只能肉眼验收。

### 电视 shell 缺一堆命令

`head` / `tail` / `stat` / `nc` / `curl` / `printf` / `xxd` 都可能没有。用 busybox：

```bash
/system/bin/busybox tail -n 25
/system/bin/busybox netstat -tln
/system/bin/busybox grep ...
```

注意：busybox 只在电视上有，**不能在 PC 侧的管道里调它**。

### `adb reboot` 被拦

有的机器策略直接拒绝 `reboot`。改用 `am force-stop` + 重新 `am start` 重启应用，
不要为了重启 App 去重启整机。

### 覆盖安装后还是旧版本

`versionCode` 没提。改代码就提版本号，然后 `aapt2 dump badging` 确认，不要看文件大小猜。

## 厂商投屏（易互动那一类）

### 第一次能投，几秒断开，之后再也投不上，只能重启电视

进程里的会话状态没释放，守护进程又把主进程一直拉活，永远是脏的。

```bash
am force-stop <包名>
busybox pkill -9 -f <进程关键字>
busybox pkill -9 -f <守护/服务关键字>
sleep 2
busybox pkill -9 -f <进程关键字>     # 守护会拉活，补一刀
am start -n <包名>/<入口Activity>
```

上面这几条就是手动版本，写成脚本或 App 都行。本项目早期有过一个「厂商投屏重置」小工具，
2026-11-12 已经移除（那套厂商投屏没声音，实际不值得留着）。要做通用版，正确方向是
**让用户自己填包名和入口**，或装完扫 `pm list packages` 让用户点选——不要猜包名，猜错会杀掉不相干的进程。

### 手机端装新版反而连不上

厂商投屏常见：电视端版本封顶，手机端新版改了发现协议（比如去掉了 mDNS 库）。
**用电视上那个"扫码下载"的二维码拿配套版本**，别用应用商店的最新版。

### 厂商投屏没有声音

多数国产厂商的镜像通道只推视频，日志里连一条 audio 记录都没有。这是产品设计，
不是配置问题——想要声音只能走自写方案。
