# 通用化改造指南（换一台电视）

这套工具不是为某一台电视写的。但"装上去就能用"和"真能跑"之间还差着几步现场确认。
这份文档就是那几步。

---

## 第一步：先测底线，别先动手

| 要查的 | 怎么查 | 为什么重要 |
|---|---|---|
| Android 版本 | `adb shell getprop ro.build.version.sdk` | 低于 14 电视端装不上；低于 29 手机端抓不到内录声音 |
| ABI | `adb shell getprop ro.product.cpu.abi` | 只有 armeabi-v7a 也能跑（本工具不依赖 native 库） |
| 分辨率 | `adb shell wm size` 或 `dumpsys display` | 决定显示区算法和编码尺寸 |
| 是否 root | `adb shell id` 看 uid，或 `su -c id` | 重置类工具要靠 root 才能杀系统级进程 |
| 有没有 `screencap` | `adb shell screencap -p /data/local/tmp/a.png` 然后看字节数 | 为 0 就只能靠 uiautomator 验证界面 |
| 能不能装第三方 APK | `adb install` 一个测试包 | 有的固件锁了安装来源 |

顺手记下这几个值，后面调参全靠它：

```bash
adb shell getprop ro.product.model
adb shell getprop ro.product.name
adb shell getprop ro.board.platform
```

---

## 第二步：投屏两端基本是通用的

电视端只需满足：**API 14+、能硬解 H.264 Baseline**。

需要按机器调整的只有两处：

1. **编码尺寸与码率**（`MirrorService`）：默认长边 1280、5 Mbps、30 fps。
   1GB 内存、老双核的机器如果卡，降到 1024 长边 / 3 Mbps / 25 fps。
2. **显示区算法**（`MirrorActivity.adjustSurface`）：默认等比居中。改成裁边填满见
   `02-投屏协议与实现.md`，但要想清楚"边缘一条看不见"能不能接受。

**不要动**：

- `Baseline + AVCLevel31`：老解码器用 High profile 直接不出图；
- 音频的 `audio/mp4a-latm` 44100 双声道：改采样率会让老 AudioTrack 播成噪音；
- `awaitFreshSurface`：SurfaceView 改尺寸必重建 Surface，跳过这步必黑屏。

## 第三步：厂商投屏要不要留

这里不再提供"重置工具"了（早期有一个专门杀康佳 `com.konka.kkmultiscreen` 的小 App，
2026-11-12 移除）。判断标准很简单：**厂商投屏如果不传音频，就直接放弃，别修**。
它没声音这是产品设计层面的缺失，不是能用补丁救回来的 bug。

如果决定放弃，正确做法是**卸载 + 清干净**，而不是禁用：

```bash
adb shell "pm uninstall <包名>"
adb shell "ps | busybox grep -i <关键字>"       # 看有没有守护进程/子进程
adb shell "busybox pkill -9 -f <剩余进程关键字>"
```

注意三个点：

1. 有的包在 `/data/app` 下（可 `pm uninstall`），有的在 `/system/app`（只能用 root 删 APK 文件）。
2. 厂商投屏常带一个 `:xxxGuard` 守护进程和一个 fork 出来的子进程（比如康佳的 `tvliveserver`），
   主进程卸掉之后它们可能变成孤儿继续跑，要单独 `pkill`。
3. **自绘桌面要手动清条目**：Aerial 这类桌面会把"已安装但不在 order 里"的包自动追加回列表，
   所以不卸载、只改配置是没用的；而且要删 `layout.xml` 的 order 项与 `tiles.xml` 的条目，
   push 回去后属主/权限要还原（`chown 10042:10042` + `chmod 660`），否则桌面读不到会重建默认布局。

## 第四步：厂商投屏"脏状态"是普遍现象，但机制各家不同

通用排查顺序：

```bash
# 1. 看这个厂商投屏有几个进程（有没有守护）
adb shell ps | busybox grep -i -E "cast|mirror|screen|multi"

# 2. 看它开了哪些端口
adb shell "busybox netstat -tln | busybox grep -E ':7[0-9]{3}|:8[0-9]{3}'"

# 3. 复现一次断线，看是谁先死
adb shell "logcat -d | busybox grep -E 'Activity pause timeout|onDestroy|force-stop'"
```

判据：如果断线时出现 `Activity pause timeout for ActivityRecord <厂商镜像页>` 然后 `onDestroy`，
就是系统超时把页面杀了但进程还留着脏会话——跟康佳同一类问题，只是进程名不同。

## 第五步：装完要验收的清单

不要靠自己"看感觉"，按这个表过一遍：

- [ ] 电视端启动后日志有 `监听端口 9000`、`自动发现服务监听 9100`
- [ ] 手机点开始，**不填 IP** 就能搜到电视
- [ ] 授权后电视出画面，方向正确
- [ ] 通知栏出现"正在投屏 WxH · 音量 N%"，点它回到 App
- [ ] 点停止后通知消失
- [ ] 手机转横屏：弹**一次**授权，弹完直接续上，不闪回 App 界面
- [ ] 转回竖屏：同样只弹一次
- [ ] 手机端滑块调到 0，电视彻底静音
- [ ] 退出手机 App 再进，音量仍是上次调的值
- [ ] 电视重启（换 IP）后，手机点开始仍能搜到
- [ ] 手机息屏 1 分钟再亮，投屏没断

老固件没法截图的话，界面验收只能靠 `uiautomator dump` + `dumpsys window` 看 `mCurrentFocus`。

## 第六步：给别人用之前，改掉这些

1. **签名**。本工具用的是一个自签名 keystore，别人装会被提示"未知来源"。公开发布请自己生成一个
   并写进 README，别让别人以为是从可信渠道来的。
2. **版本号**。每次改代码都提 `versionCode`，否则用户手机上覆盖安装会被当成同一个包缓存。
3. **默认音量**。不同电视功放不同，默认 15% 在有的机器上仍偏大。给别人用建议默认 10%，
   并在说明里写清"用 App 里的滑块调，不要动电视系统音量"。
4. **厂商投屏工具**。如果你没改成通用版，就在 README 里明确写"仅适配 XX 品牌"，
   而不是让别人装了之后发现杀错进程。
